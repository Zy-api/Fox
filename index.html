常见问题与避坑指南

如何开始部署

先到 GitHub Settings → Developer settings → Personal access tokens 创建 PAT，勾选 repo + pages 权限；在「设置」页保存并校验 PAT，再到「项目」绑定仓库，最后到「部署」开启 Pages。

PAT 获取与权限

PAT 需要 repo（读写仓库）与 pages（管理 Pages）两个权限范围。令牌仅存本机 localStorage 并以 AES-GCM 加密，前端代码不含任何密钥。

Pages 无法访问

首次开启 Pages 后需等待 1~3 分钟生效；仓库根目录需存在 index.html；若遇超时，本工具会自动清理旧 workflow 并推送 .nojekyll 加速部署。

验证码收不到

注册/找回密码时点击发送验证码，系统通过 EmailJS 真实下发 6 位码到填写邮箱，同时本地下发到 verify.html。若未收到请检查邮箱地址与 EmailJS Service/Template 配置。

GitHub OAuth 用不了

点「GitHub OAuth 授权登录」提示"请先配置 OAUTH_CLIENT_ID"时：在 index.html 搜 const OAUTH_CLIENT_ID="" 填入你的 GitHub OAuth App 的 Client ID 即可。Callback URL 填 http://你的域名/callback。若想更安全（不暴露 Secret），同时启动配套 oauth-server.js 并把 OAUTH_BACKEND 设为后端地址。

国内加速链接

国内加速镜像地址为格式示例，实际可用需你在腾讯云 EdgeOne Pages 控制台绑定对应域名并开启加速；GitHub Pages 原生地址部署成功后即可直接访问。
